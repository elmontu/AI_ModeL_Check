# PRD-23 — restricted pilot plan and readiness

Status: **in progress**. Local planning controls are implemented. No agency pilot
has started. All eleven PRD-22 production blockers remain open. Provider, region,
actual agency appointments and GitHub authentication remain pending.

## Implemented boundary

production_pilot declares one exact public Wine128 candidate, seven named fixture
people, one recipient and one planning interface. It records prospective scope,
a bounded synthetic planning window, support and suspension responsibility,
current independent local plan review and explicit go/no-go criteria.
All query and pilot-delivery limits are zero. No run, admit, activation, grant or
model-delivery method is exposed by this service.

The fixed interface is in_process_plan_only. Named fixture people are owner,
policy authority, operator/support, assessor, release authority/suspension owner,
auditor and recipient. These generated people are not agency appointments.
The exact candidate, assessment manifest/key, finding catalog and
agency/project/case bindings cannot be substituted or broadened. New models,
recipients, interfaces, people and private datasets require separately evidenced
scope and agency acceptance.

The planning window may lie within synthetic times 1000–1100. This bounds local
planning review only; original gateway activation/grant/evidence lifetimes are
unchanged. The real agency pilot's duration and workload limits require approval.

## Exact historical evidence capability

VerifiedAssessment requires a current-source matching PRD-22 packet and externally
retained manifest/key hashes. It authenticates owned observation, raw candidate
and registration buffers against exact pinned manifest entries, validates the
public profile and case, and re-verifies the complete packet. Repeated verification
does not carry current identity, agency acceptance or live permission.

Historical packets from earlier milestones are preserved. PRD-22 hashes all
package Python, so the pilot rehearsal generates a new matching assessment after
pilot source freezes. Prior packets are neither rewritten nor restamped. A
different implementation needs its matching historical build for replay.

The capability is an exact registered in-process object. Caller dictionaries,
duck types, forged objects and serialized data cannot create it. It retains
physical root/manifest/key identities. Changed or missing evidence, transient
buffer substitution and changed current source fail closed.

Historical integrity is not reconstructed attack execution, privacy clearance
or independent agency custody. The packet contains public model bytes and locally
generated evidence. Its original scientific and deployment limits remain.

## Current signed planning lifecycle

The service first enrolls all seven raw signed credentials with exact canonical
people, case scope and current server-side roles. It records the current signed
producer, accepts one immutable owner proposal, then requires a distinct assessor
and release authority for local acknowledgment.

Every enabling mutation checks packet integrity before one final shared timestamp
for all original roster and decision participants. Current roles, scopes, MFA,
key/authority revisions and the planning window are checked after expensive work.
Owner/operator aliases cannot become independent reviewers. Current local plan
review does not restore a prior PRD-22 finding approval.

Local planning states are awaiting enrollment/producer/proposal, proposed,
assessed, acknowledged, suspended and withdrawn. Suspension and withdrawal
require the current named release authority and remain available when other
participants or evidence have become stale. Resume requires healthy exact
evidence and all original current participants. Expired credentials cannot be
replaced by restoring serialized records.

The bounded 32-event history reserves restrictive transitions. Withdrawal is
terminal. Saved records are historical; a fresh instance has no enrolled roster,
proposal or acknowledgment. Stale history can remain readable to a current
authorized named reader while local_planning_ready stays false.

Suspension is scoped to this local plan. It does not revoke an independently
created PRD-18 gateway activation. Actual deployed suspension must control every
agency delivery route and retain its own current-authority evidence.

## Go/no-go and agency handoff

Local planning readiness records exact public evidence and current named review.
Production readiness always remains **no_go**, with pilot_admission,
authorization_eligible, model_delivery, private_data_admitted and
independent_agency_acceptance false. Local acknowledgment cannot close the
PRD-22 deployment, isolation, identity/key, custody, private-cohort, scientific,
DP-accounting, scale, ownership, agency-acceptance or publication findings.

Before an actual restricted pilot, the agency must provide:

| Required item | Acceptance record |
| --- | --- |
| Named accountable people | Sponsor, service owner, data steward, independent security/scientific assessors and release authority |
| Exact pilot scope | Business purpose, classification, model/data versions, protected units, users, recipients and interface |
| PRD-22 assessment | Deployment tests, scientific review, verified retests and permitted residual-risk decisions |
| Workload limits | Duration, user/query/byte/model limits, performance objectives and recovery criteria |
| Operations | Named support rota/contact, escalation, current suspension authority and every-route shutdown exercise |
| Admission decision | Signed go/no-go bound to exact scope, current evidence and rollback/suspension plan |
| Exit evidence | Predeclared success, failure and retirement criteria for PRD-24 handover |

The architecture remains portable across agency private clouds. The agency may
be a large public-health body such as a CDC/MOH or another sector. Actual private
cohorts and named government users are not supplied by the public fixture.
