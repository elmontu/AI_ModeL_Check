# Framework audit — 2026-08-22

## Executive result

MRA has a thoughtful fail-closed decision model, strict Pydantic inputs, replayable mathematical certificates, and a sound architectural separation between inert evidence evaluation and executable model workers. It is an alpha reference implementation, not a safe production authorization gate.

The audit originally identified a critical provenance defect that allowed decision-critical analyzer results to be rebound after analysis. Version 0.6 resolves it with a source-observed evidence context verified before analysis and copied unchanged into every evidence record. The claimant-selected source-binding and high-severity assessment-signing defects are also resolved. This changes the finding status, not the repository's non-production designation.

## Scope and method

The audit covered the package, CLI, schemas, examples, experiment runners, integrity and audit storage, optimizer, tests, CI, and XGBoost execution paths. Static review was combined with Python 3.12 execution in an isolated `.[experiments]` environment.

The pre-change baseline discovered 101 tests: 86 passed, 2 failed, and 13 errored. Fourteen failures/errors were caused by Windows CRLF conversion changing hash-bound JSON bytes; one required generated files from the ignored `output/` directory. The declared CI environment also omitted dependencies imported by discovered tests.

## Findings

### Critical — evidence is rebound after analysis

DP/attack inputs contain no artifact, complete-interface, or decision-game hash. [`AssuranceEngine.assess`](../src/model_release_assurance/engine.py) now verifies the complete framework-owned analyzer payload, including routing, against the source, but it still stamps the current request's artifact, interface, population, and game hashes onto analyzer output after analysis.

An accountant or attack result for one model can therefore be reassigned to another model or threat. Tree linkage binds an interface observation but still does not bind the artifact.

Required remediation: add mandatory artifact, full interface, population snapshot, and decision-game bindings to every analyzer input and evidence source. Validate them before analysis; do not manufacture them on output.

### Critical — the claimant selects provenance fields

[`AnalyzerProvenance.bound_fields`](../src/model_release_assurance/models.py) requires only one field. [`verify_provenance_binding`](../src/model_release_assurance/integrity.py) checks only that list. A request can bind an innocuous field while changing epsilon, counts, completeness flags, confidence, or validation claims.

Required remediation: remove claimant-controlled coverage. Define an immutable required payload per analyzer, preferably hashing the complete canonical analyzer result plus routing and release bindings.

**Refresh status:** the claimant-selection part is resolved. `verify_provenance_binding` now requires `bound_fields` and the evidence-source object to equal the complete framework-owned analyzer payload, including analyzer and threat routing, defaults, confidence, comparison family, counts, and validation flags. Release/artifact/interface/population/decision-game binding remains the separate critical finding above.

### High — signing can omit release expiry

[`build_signed_manifest`](../src/model_release_assurance/integrity.py) accepts a report and unrelated release object but does not compare them. Only expiry is copied from the release. Verification does not require manifest expiry to equal `report.release_expires_at`.

Required remediation: before signing, verify the canonical request and release hashes against the report. During verification, require exact report/manifest expiry equality.

**Refresh status:** resolved in the post-review implementation. Signing now accepts the complete assessment request, checks its canonical hash and its release hash and report-facing fields before signing, copies expiry only from the validated report, and verification requires exact report/manifest expiry equality.

### High — incremental controlled-inference metrics cannot traverse policy validation

`ThreatContract` and `ControlledInferenceAnalyzer` support incremental attribute and reconstruction metrics, but `PolicyRule` omits them while the engine requires exact policy/threat metric equality.

Required remediation: add the metrics to the versioned policy contract and add policy-to-engine integration tests.

### High — some experiment workers load unverified executable artifacts

The inference and population-validation scripts deserialize XGBoost and `joblib` artifacts before validating the hashes recorded in their source manifests. This conflicts with [`SECURITY.md`](../SECURITY.md).

Required remediation: constrain paths below the expected run directory, verify every artifact hash before loading, and retain worker isolation.

### Medium — low-FPR confidence is not simultaneous

The membership analyzer originally created a TPR lower bound and FPR upper bound at the requested confidence individually. Familywise coverage for the joint operating-point claim needs alpha divided across both bounds and the declared comparison family.

**Refresh status:** resolved in the post-review implementation. The core now divides alpha over both membership bounds and every declared comparison. XGBoost configuration 1.1 also divides alpha across both bounds for every registered replicate seed.

### Medium — exhaustive-search rejection is not replayably exhaustive

The optimizer's search-space certificate repeats a method string and submitted IDs but contains no canonical domain or deterministic generator. That evidence can upgrade `redesign_required` to `reject` without proving that the submitted set exhausts the approved space.

### Medium — assessment freshness can change after request parsing

Some expiry checks occur when a request model is constructed, not when `AssuranceEngine.assess` executes. A long-lived in-memory request can therefore be assessed after it becomes stale.

### Medium — retained experiment caches under-bind execution

The structural OpenML cache is keyed by status and configuration hash, not implementation hash, runtime version, or artifact verification. Experiment dependencies are lower-bounded rather than sealed; the retained runtime used XGBoost 3.2.0 while this audit resolved 3.4.1.

## Test and portability findings

- Exact byte hashes require stable checkout bytes. The repository had no `.gitattributes`, so Windows converted LF JSON to CRLF and invalidated examples.
- Full test discovery imports optional numerical and experiment libraries, but CI installed only the core lock.
- A protocol benchmark unit test required generated evidence under ignored `output/` paths.
- A SQLite tamper test relied on the connection context manager to close its handle; that only commits/rolls back, so temporary-directory cleanup failed on Windows.
- No prior automated test fitted, serialized, reloaded, hash-checked, or membership-audited XGBoost.

This customization adds LF enforcement, injects synthetic retained-evidence metadata into the isolated protocol unit test, explicitly closes its SQLite handle, installs declared experiment test dependencies in CI, compiles scripts, and adds a network-free XGBoost end-to-end test.

## XGBoost integration decision

The sealed OpenML runners already use XGBoost and must not be repurposed for arbitrary local data. [`run_xgboost_audit.py`](../scripts/run_xgboost_audit.py) is therefore a separate worker outside `src/`. It supports local CSV/Parquet classification, independently fitted target/reference preprocessing, utility measurement, leaf-signature analysis, a calibrated membership attack, deterministic CPU settings, cache verification, and a deterministic release bundle that byte-binds the target model plus preprocessing.

This worker does not claim to clear a model release; version 0.6 resolves the separate core release-binding finding.

## LLM watermark and canary profile

The LLM addition is a preregistration profile, not an engine-supported evidence or clearance path. Version 1.1 separates statistical output-watermark detection from randomized training-canary auditing, places rank exposure in an auditor-only supplementary mode by default, and treats naturalistic extraction as a separate probe. A fail-closed linter checks the template and collection plan, but emits no scientific evidence. Any future worker must retain `can_clear: false` because transcript-level interactive-channel assurance is not implemented.

## Literature-driven refresh

The [check critique](check-critique-2026-08-22.md) records the detailed post-review changes. In addition to the low-FPR fix, evidence-class direction is enforced, generic analyzers reject interactive-LLM evidence, interactive protocol contracts are stricter, incremental controlled-inference policy metrics are accepted, and the XGBoost worker now binds its decision game, corrects across replicates, reports deployment-prior PPV, replays cached attack conclusions, and omits internal training fingerprints from the recipient bundle.

The release/artifact/game provenance finding is resolved in version 0.6. The production-boundary conclusion remains unchanged because trustworthy isolated workers, exact boundary arithmetic, authoritative registry/gateway enforcement and accreditation are still absent.

## Post-change verification

- Full offline suite: 133 tests passed on Python 3.12, including all-model catalog routing, required model profiles, source-context rebinding rejection, binary and multiclass XGBoost fit/serialization, deterministic release bundling, artifact-tamper invalidation, cache-key normalization, CLI execution, signing mismatch rejection, strict LLM profile validation, and sanitized runtime provenance.
- `python -m compileall -q src scripts tests`: passed.
- `python -m pip check`: no broken requirements.
- LLM audit-profile JSON, fail-closed invariants, placeholder hash syntax, and documentation links: validated.

The XGBoost tests use synthetic local data. No user dataset or production release was assessed.
