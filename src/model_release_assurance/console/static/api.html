Submit a reference test

Mutations require ordinary JSON; no custom header is needed. Browser origins must match the service host. This is a browser request boundary, not authentication.

curl -X POST http://127.0.0.1:8765/api/jobs \
  -H "Content-Type: application/json" \
  -d '{"kind":"reference"}'

Other kinds are training, language, check and assess. Check and assess require a case_id. There are no endpoints for shell commands, model uploads, signing or deployment.

To create a trained Education case, submit {"kind":"training","training":{"name":"Public sample","dataset":"sklearn-breast-cancer","preset":"xgboost-small"}}. Poll the job for milestone progress and the resulting case_id. This preset uses bundled public data without a download.

completed means execution finished. Inspect the separate scientific verdict; no result authorizes a release.

Use GET /api/capabilities for supported training presets and datasets. Use GET /api/language/models to list installed local Ollama models, then submit {"kind":"language","language":{"model":"YOUR_INSTALLED_MODEL"}}. These tests use synthetic data and inert tools; inspect controls and observed violations in the job result.

Cancel and retry accept an empty JSON object. Retry retains the original run and options; a new job ID links back through retry_of. Running jobs cannot be cancelled through this API. Failed attempts retain diagnostics and partial artifacts.

Evidence ZIPs include a SHA-256 manifest and generated files. They are limited to 64 MiB; larger runs can be downloaded file by file. Assessment bundles include audit and preflight reports. External case input bindings remain at their original paths and are not copied into the ZIP.
